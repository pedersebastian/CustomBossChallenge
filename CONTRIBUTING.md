# Development

Technical notes for building and testing Custom Boss Challenge. For what the mod does and how to install it, see the
[README](https://github.com/pedersebastian/CustomBossChallenge/blob/master/README.md).

## Building from source

1. Install the .NET SDK, MelonLoader and BTD6 Mod Helper (with the game run at least once so Mod Helper can set up
   its references).
2. Clone this repository into your BTD6 mod sources folder.
3. Build `CustomBossChallenge.sln` (for example `dotnet build -c Release`). The built DLL is copied to the game's
   `Mods` folder automatically.

`Icon.png` is generated by `tools/GenerateIcon.ps1`
(`powershell -ExecutionPolicy Bypass -File tools/GenerateIcon.ps1`).

## Running the tests

The mod ships with in-game automated tests built on Mod Helper's `ModTest`. They cover:

- tier, spawn round and skull math, and preparing the editor's challenge for a boss game
- the Random button: a thousand random setups that must all be playable, spread like the game's own randomizer
- extra tier models for every boss and Elite tier, and real games played to victory with 6 and with 2 tiers
- a vanilla and a custom Bloonarius game compared side by side (speed, health, skulls, cash, unranked)
- the ranked and co-op guards, and that every record, boss progress and badge method is still guarded after a
  game update
- restarting a custom game, and losing one to a boss that isn't defeated
- the Max Paragons limit, enforced by the game in a custom game with a real paragon placed
- saving and loading the last setup, including broken files and values out of range
- share codes: the round trip, short codes, and broken, damaged or too new codes that must never load
- hand made, malicious codes: type names, extreme values, rich text in the name, and codes that unpack to too much
  or nest too deeply
- the main menu button, and the whole Boss Creator flow in the real Challenge Editor, from editing the boss options
  to copying and pasting share codes and pressing Play, including that the normal Challenge Editor and your own
  draft stay untouched and that Play refuses unsupported modes and missing bosses

Run them from Visual Studio / Rider with the **BloonsTD6 (Tests)** launch profile, or from the game folder:

```
BloonsTD6.exe moddingDev -batchmode --modhelper.offline --modhelper.only='CustomBossChallenge;' --modhelper.noaudio --modhelper.run -q test mod CustomBossChallenge
```

The result is written to `MelonLoader/Latest.log`, e.g. `Ran 22 test(s), 22 succeeded, 0 failed`.

The screenshots in the README come from the `ScreenshotTour` test. It only runs in a windowed game started with
`--cbc.screenshots=<folder>` (and without `-batchmode`).

## Checks on GitHub

`.github/workflows/checks.yml` runs on every push and pull request, without the game:

- **Translations**: every `Localization/*.json` must be valid JSON without duplicate keys, have exactly the keys of
  `English.json` in the same order, keep its `{0}` placeholders and leave no text empty, and every text in
  `Menus/Texts.cs` must exist in English.
- **Release version** (tags only): the tag must match `Version` in `ModHelperData.cs`, which Mod Helper uses to tell
  players about updates, and `CHANGELOG.md` must have notes for it. This runs next to the release in `build.yml`, so
  it marks a bad release instead of stopping it: run it before tagging.

Both are PowerShell scripts that also run locally in Windows PowerShell:

```
powershell -ExecutionPolicy Bypass -File .github/scripts/Check-Localization.ps1
powershell -ExecutionPolicy Bypass -File .github/scripts/Check-Release.ps1 -Tag 2.3.0
```

`build.yml` is generated by Mod Helper and overwritten when the mod is built, so other checks belong in
`checks.yml`.
